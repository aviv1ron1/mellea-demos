This voice assistant runs on a single model. Rather than wiring a separate speech-to-text server in front of a language model, the speech capability is built directly into one Granite Switch checkpoint, so the application loads exactly one model and sends it audio the same way it would send text. The user's spoken question goes in as an audio attachment on the chat request, and the model returns the spoken answer's text in the same response — one request, one model, no intermediate transcription service for the application to manage.

Inside the model, audio is handled as a preprocessing cascade. When a request arrives with an audio attachment, a compact embedded ASR model (a distilled Whisper encoder-decoder) transcribes the audio into text before the language model runs. This happens in the model's input-processing stage, ahead of scheduling, so by the time the language model sees the request the audio has already become a sequence of text tokens. A single placeholder audio token in the prompt is expanded into the transcript's tokens — the number of tokens is not fixed in advance, it emerges at runtime from whatever was said. Those transcript tokens are then embedded with the model's ordinary text embeddings and fed to the decoder exactly as if the user had typed the question. Because the audio becomes real text tokens, every existing capability of Granite Switch keeps working unchanged: the control tokens that activate LoRA adapters are still detected, the switch layer still selects adapters per span, and adapters fire on audio-originated requests just as they do on typed ones.

This is deliberately a clean, swappable seam. Today the transcript tokens are embedded with the standard text embedding table, which makes the ASR stage a true preprocessing step that any Granite model could adopt. The same seam is where a trained audio projection — a learned encoder that maps acoustic features straight into the model's embedding space, the way Granite Speech does — would later plug in, upgrading the system from cascade transcription to native audio understanding without changing how the application calls the model. The alpha version proves the single-model, single-load developer experience; the projection upgrade improves fidelity behind that same interface.

The benefit of the one-model design is operational simplicity. Developers deploy one checkpoint to one inference server, scale it as one unit, and get audio input for free alongside text — no second service to host, no extra network hop between transcription and generation, and no separate model to keep in sync. The transcription is fast enough to run inline, and when a GPU is available the embedded ASR runs there for very low added latency.
